## 2. 数据结构

### 2.1 存储后端

- 数据库名 `decor-accounting`，**版本 2**；后端在 IndexedDB 与内存 Map 之间自动降级（受限沙箱走内存 + 演示数据）。
- 后端一旦选定**不再切换**（`_backendSettled` 锁），避免迟到的 open 成功回调把数据"变没"。

### 2.2 对象仓库（8 个）

| 仓库 | keyPath | 索引 | 说明 |
|---|---|---|---|
| `projects` | `id` | — | 装修项目 |
| `transactions` | `id` | `byProject`、`byDate` | 流水（收入/支出/转账） |
| `parties` | `id` | — | 往来单位 |
| `attachments` | `id` | — | 凭证图片（存 `Blob`） |
| `reminders` | `id` | `byProject` | 收付款节点 |
| `meta` | `key` | — | KV 配置 |
| `snapshots` | `id` | `byCreatedAt` | 本地全量快照（保留最近 7 份） |
| `trash` | `id` | `byDeletedAt` | 回收站（保留 30 天） |

### 2.3 字段级模型

**projects**（≈18 字段 + 2 个嵌套数组）
```
id  name  clientName  phone  address  houseType  buildArea  constructArea
manager  designer  contractAmount  costBudget  startDate  endDate
status: ongoing | finished | settled
stages[]:   { id, name, done, date, planStart, planEnd }
planItems[]:{ id, cat, amount }
createdAt  updatedAt
```

**transactions**（收入/支出/转账三类共用一张表，靠 `type` 区分，约 20 字段）
```
公共：id  projectId  type: income|expense|transfer  amount  date  time
      method  account  partyId  partyName  note  attachmentId  createdAt
收入：subType（首付款/进度款/尾款/增项款）
      invoiceStatus（已开/未开）  invoiceType  taxAmount
支出：category（材料费/人工费/分包费/管理费/其他）  subCat
      region（客厅/卧室/厨房/卫生间/阳台/全屋/其他）
      trade（水电/泥瓦/木工/油漆/安装/其他）  material  planCat
转账：fromAccount  toAccount
```

**parties**
```
id  name  type: client|supplier|worker|manager|designer|other  phone  note
payStatus: unpaid | paid | reconciled     createdAt
口径：client = external（外部），其余 5 类 = internal（内部）
```

**reminders**　`id projectId kind:receive|pay title amount dueDate note done createdAt`

**meta（KV 配置，业务规则的实际载体）**

| key | 内容 |
|---|---|
| `theme` | `paper`（暖纸账本，默认）/ `dark`（墨绿夜读） |
| `hideMoney` | 金额脱敏开关 |
| `demoMode` / `initialized` | 演示态 / 首次启动标记 |
| `notifyEnabled` / `remindDays`(3) | 通知开关 / 节点提前提醒天数 |
| `budgetAlertPct`(80) / `stageAlertDays`(3) | 预算阈值% / 工期提前天数 |
| `accounts[]` | 账户表 `{id,name,opening,note}`（现金/微信/支付宝/银行转账） |
| `catTree` | 统一分类树（5 大类 + 19 子类） |
| `txTemplates[]` | 记账模板 |
| `stageTemplate[]` | 默认施工阶段（开工→水电施工→水电验收→泥工进场→木工交底→竣工） |
| `cycleItems[]` / `cycleDone` | 周期记账规则与已处理期次 |
| `homeBoard{order,hidden}` | 首页看板区块显隐与排序 |
| `lastAutoSnapshotAt` | 上次自动快照时间（>24h 自动存一份） |

> 另有 `localStorage['notifyLog']`：通知按天去重的键表（`{去重键: 日期}`，60 天清理）。

### 2.4 备份格式（`exportAll` / `importAll`）

```json
{ "app": "decor-accounting", "schema": 1, "exportedAt": "ISO",
  "stores": { "projects":[], "transactions":[], "parties":[],
              "reminders":[], "attachments":[{id,type,createdAt,b64}], "meta":[] } }
```
- 附件以 **base64** 内联；导入返回 `{imported, failed, failures}`，全失败才抛错。
- **导入前调用方需先存 `pre-import` 快照以便反悔**（`Snapshots.restore` 内部也会再留一份）。

> ⚠️ 迁移注意：`app` 字段与 `DB_NAME` 仍是 `decor-accounting`（历史遗留）。品牌改名「工账」后
> **不建议改这两个标识**——改了会让旧备份与旧库"认不出来"。改名只应在展示层（UI 文案、应用名）生效。

```
                      │

        scripts/verify.js ──门禁──▶ 上述全部（构建产物 / SW 清单 / Token / 演示数据口径 / Capacitor 完整性 / 品牌一致）
```

**关键约束**：`build.js` 是「源文件 → 可运行产物」的唯一桥梁，安卓化时是**必须改造**的第一环（已完成）。

### 7.2 外部依赖：8 类浏览器 API（安卓化的全部改造点）

| API | 调用点 | 用途 | 原生替代 | 优先级 |
|---|---|---|---|---|

| `navigator.clipboard` / `execCommand` | **2 + 2** 处 | 复制对账单 | `@capacitor/clipboard` | P1 |
| `indexedDB` | `db.js` | 全部业务数据 | WebView 内可用（持久化到 App 私有目录）；可选 `@capacitor-community/sqlite` | P2 |
| `FileReader` / `URL.createObjectURL` | `db.js` + `app.js` | 凭证图片存取与预览 | WebView 内可用；可选 `@capacitor/filesystem` | P2 |
| `SpeechRecognition` | **1** 处 | 备注语音输入 | `@capacitor-community/speech-recognition` | P3 |
| `localStorage` | `notifLog()` | 通知按天去重 | WebView 内可用；可选 `@capacitor/preferences` | P3 |
