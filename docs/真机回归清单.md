# 真机回归清单（A3）

> 本清单里的项目**依赖真实手机环境**，headless 自动化跑不到，必须手工执行。
> 每项都标注了「怎么操作 / 期望结果 / 不通过时看哪里」。
>
> - 第 1~7 组：网页版 PWA（安卓 Chrome 打开，添加到主屏幕）
> - **第 8 组：安卓 APP「工账」专属**（安装 APK 后执行，覆盖通知预排程/原生相机/返回键/分享/备份）

## 0. 准备

| 项 | 内容 |
|---|---|
| 设备 | 安卓手机，Chrome 最新版 |
| 安装 | 把 `index.html` 与 `sw.js`、`manifest.webmanifest`、`icon.svg`、`css/`、`js/` 一起部署到任意 HTTPS 静态托管（或本地局域网 HTTP 亦可，SW 需 HTTPS 或 localhost） |
| 添加到桌面 | Chrome 菜单 → 「添加到主屏幕」，之后从桌面图标打开（这一步才是 PWA 模式，SW 才生效） |
| 准备数据 | 首次打开会自动载入演示账本（2 项目 / 8 笔流水 / 5 往来 / 2 收付节点），足够覆盖下面大部分用例 |

## 9. 真机适配修复（2670×1200 / DPI 460 实测反馈，2026-10-31）

> 背景：`targetSdk 36` 强制 edge-to-edge，内容会画进状态栏与手势条区域。
> 本机 CSS 原先只用 `env(safe-area-inset-*)`，而该设备的 Android WebView 对 `env()` 恒返回 0
> （Chromium bug 461332423），导致顶栏被系统图标压住、底部导航被手势条遮住。
> 修复：改用 Capacitor `SystemBars` 注入的 `--safe-area-inset-*` 变量（`env()` 作兜底），
> 全站统一引用 `--sa-top / --sa-bottom / --sa-right / --sa-left`。

| # | 操作 | 期望 | 检查点 |
|---|---|---|---|
| 9.1 | 冷启动看首页 | 顶部「工账」标题**完整可见**，不被系统图标（时间/电量/信号）压住；状态栏背景与顶栏同色无白条 | `#topbar { padding-top: var(--sa-top) }` |
| 9.2 | 看底部导航 | 5 个 Tab 图标与文字**完整**，与手势条（小白条）之间有间距，不被遮挡 | `#tabbar { padding-bottom: var(--sa-bottom) }` |
| 9.3 | 看右下角「＋」悬浮按钮 | 不压在手势条上 | `.fab { bottom: calc(... + var(--sa-bottom)) }` |
| 9.4 | 项目详情页 → 看「编辑/复制/对比/删除」 | 四个按钮**全部在屏幕内**；放不下时自动换成两行，无横向滚动 | `.btn-row { flex-wrap: wrap }` |
| 9.5 | 项目详情页 → 左右滑动 | 页面**不能**横向滚动（无横向溢出） | `#app { overflow-x: clip }` |
| 9.6 | 施工阶段 → 看三个日期输入 | 「预计起/预计止/实际完」完整可见 | `row2` 已有 `flex-wrap:wrap` |
| 9.7 | 打开任意弹窗（如记账） | 底部按钮不贴手势条，有安全间距 | `.modal { padding-bottom: ... + var(--sa-bottom) }` |
| 9.8 | 流水页 → 进入批量管理 | 底部批量条不压手势条 | `.batch-bar` |
| 9.9 | 切换「墨绿夜读」→ 重复 9.1/9.2 | 深色主题下同样正常，状态栏图标变浅 | `applyTheme()` |

> 复验方式：`npm run apk` 重新出包 → `adb install -r android/app/build/outputs/apk/debug/app-debug.apk`
> 若 9.1/9.2 仍不生效，用 `chrome://inspect` 在 Console 执行
> `getComputedStyle(document.documentElement).getPropertyValue('--safe-area-inset-top')`
> 看返回值是否为 0 —— 若为 0 说明注入未生效，需检查 `capacitor.config.json` 的 `plugins.SystemBars` 配置。

## 无法在本环境自动化的原因（存档说明）

以下项依赖真实硬件/系统组件，CI 与 headless 均无法覆盖，必须人工执行：

- 系统通知（Notification API + SW push，需真实授权与系统通道）
- 相机与相册（`<input type="file" capture>` 需真机相机）
- 系统分享面板（`navigator.share` 需 Android Sharesheet）
- IndexedDB 持久化（headless 下 IndexedDB 时有时无，且 profile 一关即丢）
- 系统大字体（需真实系统字体缩放设置）
