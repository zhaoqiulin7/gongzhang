## 1. 为什么版本号是 v2.11.0，UI 却像旧版？

本项目是 **Capacitor 混合架构**：原生外壳只负责「装」一个 WebView，整个界面都是网页。
**版本号**和 **UI** 来自两套完全独立的位置，改其一不会影响另一套。

| 维度 | 来源 | 说明 |
|---|---|---|
| 应用版本号 | `android/app/build.gradle` 的 `versionName` / `versionCode` | 决定安卓「应用信息」里显示的字串 |
| 实际 UI | 打包进 APK 的 Web 资源 `android/app/src/main/assets/public/` | 由 `www/` 经 `npx cap sync android` 复制而来 |

**根因**：把 `www/` 的改动同步进原生工程，必须执行 `npx cap sync android`（= `cap copy` + `cap update`）。
只改 `build.gradle` 的 `versionName`，或只重建 `www/`，都不会自动更新 `assets/public/`。
因此会出现「版本号 2.11.0，但 APK 里装的还是上一版 UI」的脱节现象。

你提到的几种可能原因，对应本项目真实情况：

- **构建缓存未清理**：Gradle 编译缓存不影响 `versionName`，但**资源不同步**才是 UI 旧的主因——`assets/public/` 是旧副本，`cap sync` 没跑。
- **资源或布局未更新**：即上述 `assets/public/` 未重新同步，仍停留在旧版 Web 包。
- **版本号配置与实际代码不一致**：`build.gradle` 说 2.11.0，但打包资源说旧版，两者脱节。

> 一句话：改了「版本号那张皮」，没改「界面那张皮」，且 APK 根本没重新构建安装。

## 2. 如何确认 APK 是否真的是 v2.11.0 构建产物

APK 固定输出在：`android/app/build/outputs/apk/debug/app-debug.apk`

验证方法（任选其一，越靠前越权威）：

1. **构建元数据（最直接）**：读同目录 `output-metadata.json` 的 `versionName` / `versionCode`——这是该 APK 的构建记录。
   ```json
   "versionCode": 4,
   "versionName": "2.11.0"
   ```
2. **从 APK 本身读版本号（最权威，独立于源码）**：需 Android SDK `build-tools` 里的 `aapt`
   ```bash
   aapt dump badging app-debug.apk | findstr /i version
   # 输出含 versionName='2.11.0' versionCode='4'
   ```
3. **检查打包的 UI 资源**：把 APK 当 zip 解压，看 `assets/public/index.html` 的标记
   - 含 `tab-add` / `hero-card` → 旧版（v2.12 视觉改版）
   - 含「对账」tab 且**无** `tab-add` → 当前稳定版（v2.11.0）
4. **构建时间戳**：APK 文件 `LastWriteTime` 应与你回滚/同步操作的时刻对照；也可 `unzip -l app-debug.apk` 看内部条目时间。

**实测记录**（本机）：回滚前该 APK 曾为 `versionCode 5 / versionName 2.12.0`（旧版产物）；
经 `cap sync` + 重新 `assembleDebug` 后已变为 `versionCode 4 / versionName 2.11.0`，大小约 8.38 MB。

## 3. 正确的构建流程（cap sync → 打包）

环境已固化在 `scripts/build-android.sh`（关键坑点见脚本注释）：

- 必须用 **JDK 21**（系统 JDK 27 过新，Gradle 会报 `Unsupported class file major version 71`）。
- Gradle 发行源走**腾讯云镜像**（官方源不通）。
- `scripts/env.sh` 负责固定 JDK21 / `ANDROID_HOME` / 镜像。

一条命令跑完「构建 Web → 同步原生 → 打包」：

```bash
bash scripts/build-android.sh            # debug APK
bash scripts/build-android.sh release    # release APK（需签名环境变量）
```

分步等价操作（排查时用）：

```bash
node build.js                 # 1. 重建 www/（Web 资源）
npx cap sync android          # 2. 关键：把 www/ 同步进 assets/public（修复 UI 不一致）
cd android && gradlew assembleDebug --no-daemon --no-build-cache   # 3. 基于当前 build.gradle 打包
```

> 注：`cap sync` 的 `update` 步骤可能在本机被「批量删除安全护栏」拦截（插件原生文件 > 500 个待删），
> 这是**非致命**的——只要插件配置未变，被保留的旧目录不影响打包。核心的 Web 资源复制（`cap copy`）已成功即可。

