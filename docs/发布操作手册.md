# 工账 · 发布操作手册

> 面向发版人。目标：一条命令产出可上架的签名包，且过程可复现、可验签。
> 版本基线：**2.10.0 / versionCode 3**。

---

## 1. 发版前检查清单

```powershell
npm run verify          # 静态门禁：必须 0 失败 0 警告
npm run build           # 重新产出 www/ 与单文件 index.html
```

必查项：

- [ ] `sw.js` 的 `CACHE` 版本号已递增（改了 js/css 却不递增 → 真机拿不到新资源）
- [ ] `package.json` 与 `android/app/build.gradle` 的版本号已同步
- [ ] `versionCode` 已 +1（**不可回退**，否则用户无法覆盖安装）
- [ ] 真机回归清单「结果回填」已更新，无 P0 阻断项

## 2. 出包

### 2.1 Debug（自测 / 给他人试用）

```powershell
npm run build
npx cap sync android
npm run apk
# 产物：android/app/build/outputs/apk/debug/app-debug.apk
```

### 2.2 Release（上架用，签名 + 混淆）

```powershell
$env:JAVA_HOME = "C:\jdk21\jdk-21.0.2"
$env:PATH      = "C:\jdk21\jdk-21.0.2\bin;$env:PATH"
$env:ANDROID_HOME     = "$env:LOCALAPPDATA\Android\Sdk"
$env:ANDROID_SDK_ROOT = $env:ANDROID_HOME
$env:ZX_KEYSTORE     = "$PWD\android\gongzhang.jks"
$env:ZX_KEY_ALIAS    = "gongzhang"
$env:ZX_KEY_PASSWORD = "Gz#2026!KeyStore"

cd android
.\gradlew.bat assembleRelease bundleRelease --no-daemon --no-build-cache
cd ..
```

产物：

| 文件 | 用途 |
|---|---|
| `android/app/build/outputs/apk/release/app-release.apk` | 直接安装 / 国内商店上传 |
| `android/app/build/outputs/bundle/release/app-release.aab` | Google Play 上传 |

> 若未设置 `ZX_KEYSTORE`，Gradle 会**退回 debug 签名**并在日志里告警——这种包**不能上架**。

## 2.3 已知环境坑：`cap sync` 报 `update android - failed`

某些带「批量删除保护」的开发环境里，`cap sync` 会在清理 `android/capacitor-cordova-android-plugins`（上千个文件）时被拦下，日志形如：

```
× update android - failed!
[error] Error: [safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED] {"count":1319,...}
```

**判定是否有影响**：看 `android/app/capacitor.build.gradle` 的 `dependencies` 是否已列出全部插件（含新增的）。
上面几步（复制 web 资源、更新插件清单、写 `capacitor.settings.gradle` / `capacitor.build.gradle`）在报错**之前**就完成了，
所以只要这个文件里有 `implementation project(':capacitor-screen-orientation')` 之类的行，**本次同步实际已生效**，可继续编译。
若确实漏了插件，手动删掉 `android/capacitor-cordova-android-plugins` 目录后再跑一次 `npx cap sync android`。

## 3. 出包后必做三项验签

```powershell
$bt = (Get-ChildItem "$env:LOCALAPPDATA\Android\Sdk\build-tools" | Sort-Object Name | Select-Object -Last 1).FullName
$apk = "$PWD\android\app\build\outputs\apk\release\app-release.apk"

& "$bt\apksigner.bat" verify --verbose --print-certs $apk   # 期望出现 Verifies、DN=CN=GongZhang
& "$bt\zipalign.exe"  -c -P 16 4 $apk                       # 无输出即通过（4 字节对齐 + 16KB 页）
& "$bt\aapt2.exe"     dump badging $apk                     # 确认 versionCode/versionName，且不出现 application-debuggable
```

---

## 4. 16KB 页对齐（Android 15+ 上架硬要求）

已验证（2.10.0）：`lib/` 下 8 个 `.so`（arm64-v8a / armeabi-v7a / x86 / x86_64）的 ELF `p_align` 均为 `0x4000`（16KB）。
升级 NDK/AGP 或更换原生库后需重新验证，方法见 `docs/上架检查清单.md` 第 6 节。

## 6. 回滚

发布后若发现严重缺陷：

1. 立刻在商店下架 / 暂停分发；
2. 修复后 `versionCode +1` 重新出包（**不能复用旧 versionCode**）；
3. 已安装用户的数据不受影响（IndexedDB 在本地，卸载才丢）。
