### P0-2　发布签名（keystore）

- **现状**：`android/app/build.gradle` 已写好 `signingConfigs.release`，但 `keystore.properties` / `.jks` 均不存在；未设 `ZX_KEYSTORE` 时 **release 包会退回 debug 签名，不可上架**。
- **目标**：生成正式 keystore，产出可上架的签名包。
- **验收**：`npm run apk:release` 与 `npm run aab` 成功；`apksigner verify --verbose` 显示 `Verifies`；签名指纹已存档。
- **所需准备**
  - `keytool -genkeypair -v -keystore gongzhang.jks -keyalg RSA -keysize 2048 -validity 9125 -alias gongzhang`
  - 环境变量 `ZX_KEYSTORE / ZX_KEY_ALIAS / ZX_KEY_PASSWORD / ZX_STORE_PASSWORD`
  - **keystore 异地备份（丢了将无法发升级包）**；密码不得入仓（已确认 `.gitignore` 忽略 `keystore.properties`）
- **工作量**：0.5 天（含备份与验证）

### P0-5　Android 15+ 16KB 页对齐验证

- **背景**：Google Play 对 targetSdk ≥35 的应用强制要求原生库支持 **16KB page size**；本项目 `targetSdk 36`，APK 内含 `lib/*/libimage_processing_util_jni.so` 等 4 个架构。
- **目标**：确认 `.so` 已按 16KB 对齐，否则上架 Google Play 会被拒。
- **验收**：`readelf -lW lib/arm64-v8a/*.so` 的 `LOAD` 段 `p_align` 含 `0x4000`；或用 Android Studio APK Analyzer 检查无警告。
- **依赖**：CMake/NDK 版本需较新（Capacitor 8 通常已处理，但必须实测）。
- **工作量**：0.5 天（不通过则需升 AGP/NDK，可能 1~2 天）

## 4. 未来可考虑的新增功能方向

| # | 方向 | 价值说明 | 依赖 / 成本 |
|---|---|---|---|
| F1 | **跨项目总进度看板**（多项目甘特叠加 + 资源冲突提示） | 同时管多个工地时，一眼看出哪个项目延期、哪个班组撞期；是「施工管理」从单项目走向多项目的关键一步 | 中；复用 `js/gantt.js` 渲染 |
| F2 | **班组 / 工人管理与工资单** | 装修行业人工成本占比高，工人出勤→工资单→成本归集打通后，项目毛利才真实可信 | 中大；需新增数据表与结算规则 |
| F3 | **材料清单（BOM）与供应商对账** | 材料费是第二大头；与「往来单位」已有结构天然衔接，可把对账周期从几天压到几分钟 | 中 |
| F4 | **施工留痕与验收单**（照片按阶段归档 → 一键生成 PDF 验收报告） | 已具备相机/相册与 PDF 导出能力，增量小；直接解决「完工扯皮」痛点，对业主交付很有说服力 | 小~中（复用现有导出链路） |
| F5 | **发票 / 小票 OCR 记账** | 减少手动录入，记账频率低是这类工具流失的主因 | 大；需接第三方 OCR（有成本与合规） |
| F6 | **云端同步与多端协作** | 老板与项目经理各看各的手机，数据不通是硬伤；也是付费点 | 很大；需后端、账号体系、冲突合并 |
| F7 | **桌面小组件**（今日收支 / 今日施工阶段） | 提升打开率与「随手记」，安卓端成本低 | 小；需原生 AppWidget |
| F8 | **导出中心扩展**（材料表 / 工资表 / 对账单 / 全项目台账 Excel） | 已自研 xlsx 生成器，边际成本极低；对「要给业主或会计交表」的场景是刚需 | 小（**性价比最高**） |
| F9 | **预算 vs 实际 偏差预警**（超支阈值推送） | 从「记账」升级为「控成本」，是记账工具的核心增值点 | 中；复用通知通道 |
| F10 | **数据看板 BI**（利润预测、现金流预测精化） | 已有 8 周预测，加深后可做「这个工地最终能赚多少」 | 中 |
| F11 | **无障碍与适老化**（大字号模式、高对比度、语音记账） | 装修行业从业者年龄偏大，易用性直接影响留存 | 小~中 |
| F12 | **Web / 桌面端同步入口** | PWA 形态已存在，做成扫码登录的只读看板给业主看进度，是差异化卖点 | 中（依赖 F6 的同步能力） |

**建议的下一步选型**：优先做 **F8（导出中心扩展）→ F4（验收单 PDF）→ F7（小组件）**，
这三个都能复用本次已经落地的 `js/gantt.js` / xlsx 生成器 / 桥接层，投入产出比最高；
F6（云端同步）是唯一能打开商业化空间的，但应等单端体验稳定后再启动。

## 5. 风险登记（持续维护）

| 风险 | 影响 | 应对 |
|---|---|---|
| keystore 丢失 | **永久无法发升级包** | 生成后立即异地备份 + 密码存密码管理器，绝不入仓 |
| 混淆误伤 Capacitor 桥接 | release 包白屏 / 原生能力失效 | 开启前先跑一遍完整真机回归作基线；`proguard-rules.pro` 保留插件类 |
| 国产 ROM 通知不弹 | 提醒功能形同虚设 | 多 ROM 实测 + 授权引导页 + 白名单说明图 |
| `env()` 类 WebView 差异 | 换机又出现安全区问题 | 已改用 `SystemBars` 注入变量；换机回归时优先查第 9 组 |
| 16KB 页对齐不通过 | Google Play 拒审 | 提前验证；不通过则升 AGP/NDK 重编 so |
| 单人不熟悉流程 | 出包/发布只在一台机器上能跑 | 用 CI 固化 `build → verify → 出包`，并把环境变量写进文档 |
